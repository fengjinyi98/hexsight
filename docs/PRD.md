## 二、项目背景与核心痛点

### 1. 项目背景

当前金铲铲之战对局高度依赖版本理解、运营节奏、同行博弈、海克斯适配、装备变通，普通玩家存在大量信息差和决策盲区：
- 只会照搬系统推荐/版本答案，不会根据实际手牌、装备调整
- 无法快速识别全场同行，硬卷内卷导致崩盘
- 特殊海克斯拿到手，完全不懂适配玩法和运营节奏
- 装备不理想、来牌不顺时，无科学过渡思路，只能靠运气
- 纯固定规则辅助无法覆盖复杂对局、特例海克斯、动态博弈场景

本项目基于Mac原生截屏+纯画面分析，不读取游戏进程、不注入、不模拟操作，以版本答案为基底+固定规则兜底+LLM智能决策，实现全自动、实时、精准的对局辅助。

### 2. 核心用户痛点

1. **选阵盲目**：只看版本答案，不结合装备/海克斯/手牌/同行
2. **过渡崩盘**：前期无稳定打工思路，中期战力断层
3. **同行无知**：无法实时感知同行数量与内卷程度
4. **海克斯废局**：特殊/冷门海克斯不会变通玩法
5. **装备劣势**：散件杂乱、无核心装备时，不会补救转型
6. **决策滞后**：全靠肉眼统计、手动切屏查看
7. **规则死板**：普通固定数值辅助，无法应对复杂动态对局

### 3. 核心价值

- **安全合规**：纯画面像素识别，零注入、零内存读取、零自动操作
- **实时决策**：全流程自动识别，无需手动操作、无需切屏统计
- **智能应变**：固定规则保证基础决策，LLM处理复杂特例与博弈场景
- **Mac原生适配**：极致轻量化，适配M4 Mini丐版性能

## 三、产品目标

### 1. 短期目标（V1.0）

1. 实现全画面数据自动识别（自身/装备/海克斯/血量/经济/人口/回合/对手侧边信息）
2. 搭建版本答案阵容库、固定规则决策引擎、内存记忆系统
3. 实现Mac置顶透明悬浮窗，实时展示基础决策建议
4. 单帧识别+决策总延迟≤100ms
5. 零本地截图存储

### 2. 长期目标

1. 接入轻量化端侧LLM，实现复杂对局智能决策
2. 对手阵容全自动识别（可选模拟切屏，开关可控）
3. 版本自适应更新
4. 支持OBS画面源接入
5. 打造"规则兜底+AI决策"的高阶智能对局顾问

### 3. 非目标

- 不开发任何自动操作、自动对局、自动点击功能
- 不读取、修改游戏内存、进程、网络数据
- 不支持Windows平台
- 不对外上传用户数据，全程本地运行

## 五、全局规则与风险声明

### 1. 核心运行规则（安全红线）

1. **纯视觉分析**：仅通过屏幕录制权限截取画面像素
2. **无任何操作干预**：不模拟鼠标、键盘、触控操作
3. **本地闭环运行**：所有识别、计算、推理、存储均在本地完成
4. **权限最小化**：仅申请屏幕录制权限
5. **对局数据隔离**：单局记忆单局清空，新对局自动重置
6. **性能熔断机制**：CPU/内存超标时自动降帧、降识别频率

### 2. 风险明确提示

本产品为第三方实时信息辅助工具，并非游戏外挂，但违反金铲铲之战用户协议中"第三方辅助工具"相关条款，存在账号警告、封禁风险。产品提供纯基础识别模式（无LLM、无切屏），为最低风险运行方案，用户可自主切换。

## 七、详细功能需求

### 模块1：Mac原生截屏与权限管理

- 首次打开自动引导开启屏幕录制权限
- 自动识别金铲铲模拟器窗口，锁定游戏画面
- 分区域精准截取：自身信息区、棋盘区、装备区、海克斯区、对手侧边区、商店区
- 截屏全程内存流转，不生成任何图片文件
- 动态帧率：常规15fps / 关键30fps / 后台5fps

### 模块2：画面识别与数据解析

- **7-segment数字解析**：金币、人口、等级等固定字体数字
- **图标模板匹配**：装备散件/成品/转职图标、英雄头像、羁绊标识（感知哈希+NCC）
- **条状扫描**：血量条、经验条像素列扫描
- **OCR兜底**：海克斯名称等动态文本识别
- 识别准确率≥95%

### 模块3：全局对局记忆系统

- 单局全局状态常驻内存，不落地存储
- 增量更新：仅变化数据刷新
- 降噪门控：连续3帧识别一致才确认更新
- 快照与恢复：每回合自动生成JSON快照，异常退出可恢复
- 自动重置：新对局/退出大厅自动清空

### 模块4：版本答案阵容库与规则引擎

- 内置当前赛季T0-T1主流阵容（初始6套）
- 每套阵容包含：核心构成、装备规则、过渡规则、同行规则、海克斯适配、劣势补救
- 开局选阵：装备适配 > 初始来牌 > 版本强度
- 同行博弈：0-1家正常/2家放缓/≥3家强制转型
- 装备补救：散件杂乱→功能性装备、纯防御→苟分运营

### 模块5：端侧LLM智能决策（V1.5）

- 复杂海克斯决策、动态变阵建议、对局博弈分析
- 双决策兜底：常规局用规则引擎，复杂局自动触发LLM
- 端侧离线量化模型（MLX + Qwen2.5-3B-int4），无需联网
- 单次推理30-80ms

### 模块6：悬浮窗UI展示与交互

- Mac全局置顶，透明毛玻璃样式
- 三档模式：极简/完整/纯预警
- 点击穿透，不影响游戏操作
- 自由拖动、透明度调节、一键隐藏

### 模块7：性能与存储管控

- M4 Mini丐版专属优化：CPU≤15%，内存≤2GB
- 自动熔断：单帧超时自动降帧、关闭LLM
- 后台休眠：游戏最小化自动暂停
- 截屏零文件落地，快照仅保留最新1份

### 模块8：OBS可选接入（V2.0）

- 支持接入OBS Mac版窗口捕获源
- 默认关闭，手动开启

## 九、业务流程

### 全流程闭环

1. 启动APP → 申请屏幕录制权限
2. 打开金铲铲模拟器 → 自动锁定游戏窗口
3. 进入对局 → 自动初始化记忆库
4. 实时截屏 → 分区域识别数据
5. 数据存入内存记忆 → 同步去噪校验
6. 判定对局场景：常规局→规则引擎 / 复杂局→LLM推理
7. 决策结果推送至悬浮窗实时展示
8. 对局结束 → 自动清空记忆
9. 退出APP → 释放所有资源

### 关键触发节点

| 节点 | 触发动作 |
| ---- | ---- |
| 开局2-1 | 识别装备+初始来牌 → 输出首选阵容 |
| 海克斯选择 | 触发LLM推理 → 输出海克斯专属玩法 |
| 2-5/3-2 | 识别过渡战力 → 输出打工/升人口建议 |
| 选秀阶段 | 识别装备 → 输出最优选秀目标 |
| 4-1节点 | 判定同行+血量+经济 → 输出D牌/拉人口决策 |
| 血量<30 | 触发保命策略 → 全力D质量提醒 |
| 同行≥3 | 触发转型决策 → 输出备选阵容 |

## 十三、附录：识别方案选型

固定分辨率（1920x1080）下的技术方案：

| 数据类型 | 方法 | 延迟 |
| ---- | ---- | ---- |
| 数字（金币/等级） | 7-segment像素模板匹配 | <1ms |
| 图标（装备/英雄） | pHash + 汉明距离查表 | <1ms |
| 条状数据（血量/经验） | 列扫描边界检测 | <1ms |
| 场景判断 | 整帧pHash场景指纹 | <1ms |
| 动态文本（海克斯名称） | OCR兜底 | ~20ms |
| 英雄头像分类 | CoreML轻量分类器（可选） | <1ms |

组合方案：场景指纹判定阶段 → 按路由分发 → 固定图标模板匹配 + 数字7-segment + 条状扫描 + OCR兜底。整体识别延迟15-30ms。
